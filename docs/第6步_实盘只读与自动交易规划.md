> 关联文档：`docs/第5步_多周期_风险管理_订单流_设计与范围.md`、`docs/交接文档_给GPT协作者_20261124.md`

## 0. 结论速览

**建议拆成 4 个阶段，每个阶段都可独立回退：**

| 阶段 | 内容 | 关键产出 | 风险等级 | 前置条件 |
|---|---|---|---|---|
| P0 | Key 与运行环境准备 | 子账户、权限、IP 白名单、`.env` 分层 | 低 | 用户操作 |
| P1 | 实盘只读 | 余额、持仓、保证金率、成交记录、账户配置 | 中（只读 Key 泄露） | P0 |
| P2 | 账户相关风控展示 | 真实保证金率/强平价/未实现盈亏，与本地手工订单分开 | 中 | P1 稳定 |
| P3 | 模拟盘下单（OKX Demo） | 签名下单链路、订单回报、审计日志、一键撤单 | 高（签名与误单） | P1 + 回测框架 |
| P4 | 自动交易（小资金灰度） | 策略执行器、硬性边界、熔断、杀开关 | 极高 | P3 + Rocket Science 级回测 + 影子跑 |

**三条硬结论：**

1. **只读与可交易必须用两把 Key、两个子账户。** 主账户永远不生成带交易权限的 Key；实盘交易 Key 只挂在独立子账户上，且永不开提现权限。
2. **P1/P2 不引入任何下单能力。** 程序现有的「订单」是本地手工记账，和交易所真实持仓必须分开展示，禁止合并成一个「持仓」数字。
3. **自动交易不是功能迭代，是资金安全工程。** 没有通过回测门槛 + 至少 4 周影子运行，不允许进入 P4；进入 P4 也必须保留人工确认与杀开关。

## 1. 现状与差距

| 能力 | 当前状态 | 差距 |
|---|---|---|
| 行情 | OKX 公共 REST，走代理，5 秒轮询 | 无（P1 复用） |
| 账户 | 完全没有私有接口调用；`OKE_API_KEY/SECRET` 配置存在但未用于签名 | 缺 passphrase、签名器、私有请求封装 |
| 持仓 | 只有本地手工订单（`user_trades.db`），数量语义是「币数量」 | 与交易所真实持仓无关联，不能混算 |
| 风控 | 本地计划风险、止损止盈、组合敞口（第 5 步） | 缺真实保证金率、强平价、真实未实现盈亏 |
| 回测 | 有预测留档 + 回验 + 绩效分桶 | 缺策略级回测框架（费用、滑点、资金曲线） |
| 下单 | 无 | 缺签名、订单状态机、幂等、审计、撤单 |

> 关键口径：**本地手工订单 ≠ 交易所持仓**。P1 起，前端必须用「本地记录」与「实盘账户」两个独立区块展示，禁止相加。

## 2. 阶段拆解

### P0：Key 与运行环境准备（用户操作，0 代码）

**目标**：在不暴露主账户的前提下，拿到最小权限、可随时吊销的实盘只读能力。

**用户需要做的事：**

1. 在 OKX 创建**独立子账户**，命名如 `oke-readonly`（只读）与 `oke-trade`（后续交易），主账户不生成任何 Key。
2. 只读 Key 权限：仅勾选「读取」；**不勾选交易、不勾选提现**。
3. 后续交易 Key 权限：仅「读取 + 交易」；**永远不勾选提现**，并绑定独立子账户。
4. 设置 **IP 白名单**。注意：本程序走本地代理访问 OKX，OKX 看到的是代理出口 IP，白名单必须填代理的固定出口 IP；若代理出口会漂移，先解决固定出口，否则不要启用交易 Key。
5. 记录 Key 的 **Passphrase**（OKX 创建时设置的口令），现有配置只有 Key/Secret，需要新增 `OKE_API_PASSPHRASE`。
6. `.env` 放置规则：
   - 开发/测试版：`backend/.env`（当前 `config.py` 的加载顺序已支持）。
   - 打包版：**exe 同级目录的 `.env` 优先**，其次包内 `.env`；正式分发时只给 `.env.example`，绝不把真实 `.env` 打进产物。
   - 测试版与打包版使用**不同 Key**；测试版只放只读 Key，交易 Key 只在灰度机器上配置。
7. 给两个子账户各留少量资金；只读账户可以零资金。

**验收**：在 OKX 后台能分别看到两把 Key 的权限、白名单、最近调用时间；吊销任一 Key 不影响另一把。

### P1：实盘只读（余额 / 持仓 / 保证金率 / 成交记录）

**目标**：程序内新增「实盘」入口，只读展示账户真实状态，不产生任何写操作。

**后端新增（建议，未实现）：**

- `backend/app/services/okx_private_client.py`：私有 REST 签名客户端
  - 签名：`HMAC-SHA256(timestamp + method + requestPath + body, secret)`，请求头 `OK-ACCESS-KEY / SIGN / TIMESTAMP / PASSPHRASE`；模拟盘加 `x-simulated-trading: 1`。
  - 复用现有代理尝试链与 `certifi` CA 策略（见 `oke_client.py`），但**不要**把私有请求混进公共行情客户端，避免 Key 进入行情调用栈。
  - 超时、限频、错误码映射（`50111` 无效 Key、`50113` 签名错误、`50114` 时间戳过期等）。
- `backend/app/services/account_service.py`：缓存 + 降级，GET 只读缓存不触发外部请求。
- `backend/app/routes/account.py`：`/api/v3/account/*`。
- 调度：账户快照默认 15–30 秒一轮，独立线程池，`max_instances=1`、`coalesce=True`；与行情 5 秒主循环解耦。

**接口草案（全部只读）：**

| 方法 | 路径 | 数据来源 | 说明 |
|---|---|---|---|
| GET | `/api/v3/account/summary` | `/api/v5/account/balance` | 总权益、可用、占用、币种余额 |
| GET | `/api/v3/account/positions` | `/api/v5/account/positions` | 真实持仓、方向、杠杆、未实现盈亏、保证金率、强平价 |
| GET | `/api/v3/account/margin` | balance + positions | 账户/逐仓保证金率、风险状态（安全/预警/危险） |
| GET | `/api/v3/account/fills` | `/api/v5/trade/fills-history` | 成交记录（分页、按 instId/时间筛选） |
| GET | `/api/v3/account/config` | `/api/v5/account/config` | 账户模式、持仓模式、手续费等级 |
| GET | `/api/v3/account/status` | 本地 | Key 是否配置、最近成功时间、错误码、`stale` |

**降级约定**：未配置 Key 或拉取失败返回 200 + `available=false` + `reason`，不抛 5xx；保留上一轮缓存并标 `stale`。

**前端**：新增「实盘」Tab（与「订单」Tab 分离）。至少包含：权益卡片、真实持仓表、保证金率/风险状态条、成交记录表、数据新鲜度与 Key 状态。

**风险**：

- 只读 Key 泄露仍可能暴露账户规模与持仓；`.env` 不入库、不出包、不截图。
- 代理被劫持会泄露请求头（含签名，不含 Secret）；优先使用可信本地代理。
- 私有接口有频率限制，刷新过快会被限流；默认 15–30 秒。

**验收**：界面数字与 OKX 网页端逐项一致；撤销 Key 后程序进入 `available=false`，不影响行情与本地订单功能。

### P2：账户相关风控展示（只读增强）

**目标**：把第 5 步的「计划风险」升级为「真实风险」，但**仍然不下单**。

**新增展示：**

- 真实保证金率、维持保证金、可用保证金、强平距离（按标记价）。
- 按币种的真实名义敞口、账户总敞口、多空净敞口。
- 本地手工订单与真实持仓的**对账视图**：按币种并列，标出「本地有、实盘无」「实盘有、本地无」「数量不一致」。
- 组合风险阈值告警沿用 `risk_settings`（权益可切换为「实盘总权益」），但只提示，不自动处置。

**边界**：

- 不把真实持仓写回本地 `orders` 表，避免污染手工记账与历史绩效。
- 不允许「一键同步持仓」这类隐式写操作；真要做，必须单列确认流程。

**验收**：能一眼回答「账户现在离强平还有多远」「哪个币种集中度最高」「本地记账和实盘差在哪」。

---

### P3：模拟盘下单（OKX Demo Trading）

**目标**：打通「签名 → 下单 → 订单回报 → 撤单」全链路，只在 OKX 模拟盘验证，不碰真实资金。

**新增能力：**

- 私有写接口封装：下单、撤单、改单、查询挂单、查询历史订单。
- 订单幂等：每次下单生成 `clientOrderId`（前缀 `oke-` + 时间 + 随机），网络重试不重复下单。
- 订单状态机：`pending → submitted → partially_filled → filled / canceled / rejected`，落本地新表（建议 `live_orders`、`live_fills`）。
- 审计：每次请求/响应、参数、错误码、来源信号 ID 全量落库，保留可回放。
- 杀开关（P3 就要做）：一键撤全部挂单 + 停止后续下单；需人工二次确认才能恢复。

**硬性限制：**

- 只允许限价单；禁止市价单作为默认。
- 单笔名义上限、单日下单次数上限在 P3 就写死，不允许 UI 绕过。
- 模拟盘 Key 与实盘 Key 物理隔离。

**验收**：模拟盘连续 2 周无重复下单、无孤儿订单；断网/代理抖动后能自动对账并恢复；所有动作可审计。

---

### P4：智能自动交易（小资金灰度）

**目标**：在严格边界内，让策略自动产生订单；任何越界都必须停下来等人。

**前置门槛（缺一不可）：**

1. 通过第 6 节的回测验收标准。
2. 至少 4 周影子运行：策略实时出信号、记录「本应下的单」，但不真正下单，逐日对账滑点与偏差。
3. 模拟盘连续 2 周稳定（P3 验收）。
4. 用户书面确认单笔/总敞口上限与熔断参数。

**自动交易允许做的事：**

- 按已冻结的策略参数生成限价单，且满足全部风控前置检查。
- 自动撤单（超时未成交）。
- 自动止损（仅限服务端条件单或本地监控 + 人工确认二选一，见下）。

**自动交易绝对不允许做的事：**

- 不允许划转资金、不允许调整杠杆、不允许开启新的合约权限。
- 不允许修改策略参数、不允许解除熔断、不允许修改上限。
- 不允许在 Key/代理异常时「重试到成功」；只允许有限次重试后停机。

## 3. Key 权限最小化与边界

### 3.1 权限矩阵

| 用途 | 读取 | 交易 | 提现 | 子账户 | 建议 |
|---|---|---|---|---|---|
| 行情（现状） | 公共接口 | - | - | 不需要 | 不需要 Key |
| P1/P2 只读 | ✅ | ❌ | ❌ | 独立子账户 | 必须 |
| P3 模拟盘 | ✅ | ✅ | ❌ | Demo 子账户 | 必须 |
| P4 实盘灰度 | ✅ | ✅ | ❌ | 独立子账户 + 固定 IP | 最后才创建 |

### 3.2 存储与分发边界

- 真实 `.env` 只存在于运行机器，加入 `.gitignore`，不截图、不贴聊天、不进文档。
- 打包产物只带 `.env.example`；打包版优先读 exe 同级 `.env`，便于换 Key 不重打包。
- 测试版与打包版 Key 分离；开发机上的 Key 不具备交易权限。
- Key 轮换流程：新建 → 验证 → 切 `.env` → 观察 24 小时 → 吊销旧 Key。
- 程序内永远不回显 Secret/Passphrase，只显示 Key 后四位与权限状态。

### 3.3 代理与 IP 白名单

- OKX 看到的是代理出口 IP；白名单填出口 IP，不填 `127.0.0.1`。
- 代理出口不固定时，交易 Key 不应启用；只读可以接受更高风险，但仍建议固定。
- 私有请求失败要区分「网络/代理失败」与「鉴权失败」，前者可重试，后者必须停机告警。

## 5. 自动交易硬性边界（写死，不可由 UI 绕过）

### 5.1 必须人工确认的动作

1. 首次开启实盘交易总开关。
2. 策略上线、下线、参数变更、切换标的。
3. 单笔名义超过「自动额度」的订单。
4. 提高任何上限（单笔、单币、总敞口、杠杆、每日次数）。
5. 解除熔断/杀开关（需二次确认 + 至少 10 分钟冷静期）。
6. 更换 API Key、子账户、代理出口。
7. 手动全平/批量撤单以外的任何批量操作。
8. 从影子模式切换到真实下单。

### 5.2 数值上限（初始建议，可下调不可上调）

| 项 | 上限 |
|---|---|
| 单笔计划风险 | ≤ 账户权益 1% |
| 单币名义敞口 | ≤ 账户权益 20% |
| 账户总名义敞口 | ≤ 账户权益 50% |
| 杠杆 | ≤ 3x（且不主动调高交易所杠杆） |
| 单日新开仓次数 | ≤ 20 |
| 同时挂单数 | ≤ 10 |
| 单日亏损熔断 | 当日权益 -3% 停止开新仓 |
| 连续亏损 | 连续 3 笔亏损暂停 24h；连续 5 笔或单日 -5% 硬熔断 |
| 滑点保护 | 限价单偏离盘口 > 0.3% 拒单 |

### 5.3 熔断与杀开关

- **三级状态**：`NORMAL → PAUSED（暂停开新仓，允许平仓）→ HALTED（停止一切下单，需人工解锁）`。
- 触发源：单日亏损、连续亏损、保证金率低于阈值、私有接口连续鉴权失败、代理连续失败、数据过期、审计写入失败。
- 杀开关三层：
  1. 配置层：`OKE_LIVE_TRADING_ENABLED=false`（默认关闭，进程启动即不加载交易模块）。
  2. 状态层：`live_risk_state.trading_enabled`，UI 一键关闭，立即撤挂单。
  3. 进程层：直接结束程序；重启后仍为关闭状态（状态持久化）。
- 恢复：必须人工确认 + 冷静期 + 重新校验 Key 权限与 IP 白名单。

### 5.4 审计不可关闭

每笔下单/撤单/改单/拒单必须记录：请求参数、响应、错误码、信号来源、当时的账户快照 ID。审计写失败时**禁止继续下单**。

## 6. 为什么必须先做 Rocket Science 级别的回测

自动交易一旦跑起来，错误会以真金白银、且以「每秒一次」的速度放大。因此回测不是「跑个胜率」，而是排除以下系统性错误：

### 6.1 回测必须满足的 12 项

1. **无未来函数**：信号只用已收盘 K 线，成交在下一根开盘或限价撮合，不允许用当根收盘价成交。
2. **费用真实**：双边手续费 + 滑点（建议 5bp + 2bp，另做 2 倍压力测试）。
3. **资金费率**：永续持仓按实际资金费率扣减。
4. **样本外验证**：walk-forward ≥ 3 折，样本外 ≥ 6 个月。
5. **样本量**：≥ 300 笔交易，且覆盖不同市场状态（趋势/震荡/高波动）。
6. **参数稳健性**：参数邻域内绩效不能断崖；只接受「平台期」参数。
7. **蒙特卡洛**：对交易顺序重排 ≥ 1000 次，5% 分位最大回撤可接受。
8. **成本压力**：2 倍费用/滑点后仍为正期望。
9. **回撤约束**：最大回撤 ≤ 15%，且恢复期可解释。
10. **收益结构**：不依赖单日/单币/单笔暴利（单一来源 ≤ 40% 利润）。
11. **执行可行性**：订单量不超过盘口深度，限价单成交率假设保守。
12. **可复现**：固定随机种子、固定数据版本，任何人可复跑出同一资金曲线。

### 6.2 通过标准（建议）

- 净 Sharpe ≥ 1.0，Profit Factor ≥ 1.3，最大回撤 ≤ 15%。
- 样本外表现不低于样本内的 60%。
- 2 倍成本压力下仍为正期望。
- 影子运行 4 周，信号到下单的偏差、滑点、漏单率均在预设范围内。

**不满足任一项 → 不进入 P4。** 这不是保守，而是自动交易的入场券。

## 7. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 交易 Key 泄露 | 资金损失 | 子账户 + 不提现 + IP 白名单 + 轮换 |
| 代理出口漂移 | 鉴权失败或误用他人出口 | 固定出口；失败即停机 |
| 本地记账与实盘混用 | 风控数字失真 | 两套数据物理分离，禁止相加 |
| 重复下单 | 超额敞口 | `clientOrderId` 幂等 + 审计 |
| 断网/重启留下孤儿单 | 失控持仓 | 启动对账 + 一键撤单 + 杀开关 |
| 参数过拟合 | 实盘亏损 | walk-forward + 样本外 + 参数平台 |
| 审计写失败 | 无法追责 | 写失败即停止下单 |
| 用户误操作 | 意外开仓 | 人工确认 + 冷静期 + 默认关闭 |
