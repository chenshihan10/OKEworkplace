## 一、真实行情链路修复

### 1.1 问题现象

界面长期显示「数据不可用」或价格明显偏离真实行情；日志里 TLS 握手失败与 404 混杂，无法判断到底是网络问题还是代码问题。

### 1.2 TLS：显式使用 certifi，绕开被污染的环境变量

本机存在一个失效的 `CURL_CA_BUNDLE=F:\PostgresSQL\16\ssl\certs\ca-bundle.frt`（路径不存在）。`requests` 在部分路径上会读取该变量，导致所有 HTTPS 请求在证书加载阶段就失败。

处理方式（不改系统环境变量、不改注册表，只在程序内部显式指定）：

```python
try:
    import certifi
    CA_BUNDLE = certifi.where()
except Exception:
    CA_BUNDLE = True
```

- 所有 OKX 请求显式传 `verify=CA_BUNDLE`
- `network_service.okx_reachable()` 同样使用该证书

涉及：`backend/app/services/oke_client.py`、`backend/app/services/network_service.py`

### 1.3 删除假数据兜底

原先 `fetch_ticker / fetch_candles / fetch_open_interest / fetch_funding_rate` 在异常时会生成随机数“兜底”，导致失败被伪装成正常数据。

现已全部删除（含 `_fallback_seed` 与 `math/random` 依赖）。失败就抛错，链路上层如实标记：

- 快照无数据 → 卡片显示「数据不可用」
- 盘口不可用 → `source = "unavailable"`
- 前端 `fallbackData` 文案统一为「数据不可用」

涉及：`oke_client.py`、`market_service.py`、`frontend/src/main.js`、`frontend/src/render/MarketCard.js`、`frontend/src/utils/format.js`

### 1.4 代理与 DNS 的现实约束（重要）

这台机器访问 OKX 有两个独立约束，缺一不可：

| 约束 | 现象 | 处理 |
|------|------|------|
| 本地代理 | 代理未启动时全部请求失败 | 需要 `127.0.0.1:12334` 在跑（Hiddify） |
| 本机 DNS 劫持 | `www.okx.com` 被解析到 `127.0.0.1` | 代理链路可绕过；OKX CLI 需使用 pilot 节点 `47.242.161.22`（`~/.okx/pilot-cache.json`） |

程序内的代理回退链：**环境变量 → Windows 注册表 → `.env` 配置 → 直连**。每个工作线程复用 `requests.Session` 并设置 `trust_env=False`，避免代理配置被二次读取，同时保留连接复用。

### 1.5 一个反面案例：本机自检不能走代理

`.env` 里的 `HTTP_PROXY` 会被 `python-dotenv` 注入 `os.environ`，`urllib.request.urlopen("http://127.0.0.1:8000/health")` 会把本机请求也发给代理。代理拒绝 localhost 后，`entry_exe` 的启动自检 30 秒超时，进程在 `console=False` 下静默退出——表现为“双击没反应”。

修复：自检显式绕过代理。

```python
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
```

同时给 GUI 启动异常补了落盘日志（`startup_error.log`），避免同类问题再次无痕。

## 二、指数价接口修正

`/api/v5/public/index-price` 在 OKX V5 返回 404，不存在该路径。

正确用法：

- 接口：`GET /api/v5/market/index-tickers`
- `instId` 用**去掉 `-SWAP` 的指数名**（如 `BTC-USDT`，不是 `BTC-USDT-SWAP`）
- 取值字段：`idxPx`

修复后「标记-指数价差」不再恒为 0，可用于判断资金费率是否异常。

涉及：`backend/app/services/oke_client.py::fetch_index_price`

## 三、刷新并行化与调度参数

### 3.1 并行抓取

每个币种一轮需要 8 个请求（ticker / candles / OI / funding / 标记价 / 指数价 / 盘口等）。串行化时单轮 13 秒以上，叠加 5 秒调度周期会不断堆积。

处理：

- `MarketService` 内部维护 `ThreadPoolExecutor(max_workers=16, thread_name_prefix="oke-fetch")`
- `_refresh_one` 把同币种的 8 个请求并行提交，再按原顺序 `result()` 汇总（保证结果顺序稳定）
- 工作线程复用 Session（见 1.4），减少 TLS 握手

### 3.2 调度参数

`backend/app/core/scheduler.py`：

```python
max_instances=3,
misfire_grace_time=20,
```

避免上一轮未结束时 APScheduler 报 `maximum number of running instances reached`。

### 3.3 实测

- 首次完整数据：约 5.2 秒
- 50 秒连续观察：0 次跳过、0 次刷新失败

## 五、打包注意事项

1. **产物只带 `.env.example`，不含真实 Key**
   spec 的 datas 使用 `('.env.example', '.')`，自 2026-11-24 起不再打包 `backend/.env`。
   首次使用：把 `_internal\.env.example` 复制到 **exe 同级目录**并命名为 `.env`，填入自己的 OKX Key 与代理；
   直接分发产物不会泄露凭据。旧版 `dist\current\_internal\.env` 已移出到 `代码备份\`。

   **配置读取顺序**（`backend/app/core/config.py`）：exe 同级 `.env` 优先 → 找不到再回退 `_internal\.env`。
   因此重新打包后只需保留 exe 同级的 `.env`，不必每次把 Key 重新贴进包内；
   直接跑 uvicorn（无 exe）时按 `backend/.env` 读取。

2. **本机自检必须直连**
   见 1.5，否则表现为“双击无反应”，且旧版没有日志、极难定位。

3. **`console=False` 必须配落盘日志**
   GUI 启动异常、服务启动异常都要写入 `startup_error.log`（位于 exe 同目录）。

4. **certifi 数据文件**
   spec 的 `collect_data_files` 已包含 `certifi`，产物中应存在 `_internal\certifi\cacert.pem`；每次打包后建议确认。

5. **spec 纳入版本管理**
   `.gitignore` 中的 `*.spec` 已移除，打包配置随代码一起演进。
