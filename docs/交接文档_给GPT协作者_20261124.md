## 1. 一句话定位

OKEworkplace 是一个**本地运行的 OKX 行情盯盘 + 五维评分 + 预测留档与回验 + 绩效统计**终端：Python FastAPI 单进程后端 + 原生 ES Module 前端 + SQLite，桌面版由 PyInstaller 打包，国内通过 HTTP 代理访问 OKX 公共接口。

**它目前不连接任何私有账户、不下单、不读取真实持仓。**

---

## 2. 运行形态与启动

| 项 | 说明 |
|---|---|
| 后端 | FastAPI + APScheduler + 后台线程/线程池，单进程 |
| 前端 | `frontend/` 原生 ES Module，无构建步骤，由后端静态托管 |
| 数据库 | SQLite：`signals.db`（分析与预测）、`user_trades.db`（本地手工订单与风险） |
| 网络 | OKX 公共 REST，代理尝试链：环境变量 → Windows 注册表 → `.env` 配置 → 直连 |
| 桌面壳 | `backend/entry_exe.py`：启动 uvicorn、端口冲突自动递增、打开本地页面、生成一次性本地 token |
| 打包 | `backend/OKEworkplace.spec`（PyInstaller） |

**开发启动：**

```powershell
# 方式一（推荐）
.venv\Scripts\python.exe backend\entry_exe.py

# 方式二
cd backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

- 开发模式下页面带 `dev=1`，前端会轮询 `/dev/frontend-version` 自动刷新；打包版不注册该路由。
- `OKE_ENABLE_SHUTDOWN` 控制 `/api/shutdown`；桌面模式默认开启，`uvicorn` 直跑默认关闭。
- 同一工作区并行开发时注意端口占用（8000 常被旧实例占用，可用 8010 等）。

## 6. 数据表与口径

### 6.1 `signals.db`（分析、预测、回验、上下文）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `signals` | 信号与评分字段、`created_at` | 判断变化或心跳时写入 |
| `analysis_snapshots` | `trend_score/momentum_score/volume_score/oi_score/funding_score/trend_phase` | 五维分项快照 |
| `predictions` | `id, symbol, direction, score, level, regime, price, reasons, created_at, verify_status, verified_at, outcome, price_after, pnl_pct` + 迁移列 `timeframe/price_type/strategy_version/verifiable/verify_note` | 只记录 LONG/SHORT；同币种同方向默认 30 分钟节流 |
| `prediction_results` | `prediction_id, symbol, horizon, price_type, entry_price, exit_price, gross_return, estimated_cost, net_return, mfe, mae, outcome, verify_status, data_quality, verified_at, note`；`UNIQUE(prediction_id, horizon)` | 每个 horizon 一行 |
| `signal_snapshots` | 压缩后的原始信号快照 | 降采样存储 |
| `order_flow_snapshots` | 买卖量、delta、delta_ratio、session_cvd、大单买卖、盘口失衡、flow_bias、quality、payload_z | 默认 5 分钟一条，不是实时逐笔 |
| `prediction_context` | `prediction_id` 主键、`mtf_resonance/mtf_alignment/mtf_json/orderflow_bias/orderflow_json/market_json` | 预测时刻的旁路上下文，可空 |

**口径要点：**

- 预测价格统一取**最后一根已收盘 K 线的 close**（`price_type = candle_close`），与回验 `exit_price` 一致。
- 回验 horizon 固定 `30m / 1h / 4h`；状态含 `verified / invalid / failed / insufficient_data`；结果 `WIN / LOSS / FLAT`（默认 ±0.1% 内为 FLAT）。
- 净收益已扣双边手续费与滑点（默认费率 0.05%、滑点 0.02%，可配置）。
- 绩效：`胜率 = WIN / 已回验`；`方向准确率 = WIN / (WIN + LOSS)`；样本 < 30 时上下文分桶只给计数。

### 6.2 `user_trades.db`（本地手工记账）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `orders` | `id, symbol, direction, entry_price, quantity, note, status, stop_loss, take_profit, created_at, updated_at` | 本地记账，**不是交易所持仓** |
| `closed_orders` | `original_order_id, ..., close_price, pnl_pct, pnl_abs, result, stop_loss, take_profit, exit_reason, planned_risk, rr` | 平仓快照 |
| `risk_settings` | `id=1, equity, risk_per_trade_pct=1, max_portfolio_risk_pct=6, max_symbol_concentration_pct=50` | 单行；`equity` 未配置时风险占比返回 null |
| `risk_events` | `order_id, symbol, event_type(sl_hit/tp_hit), price, level, created_at` | 30 分钟冷却去重，仅提示 |

**口径要点：**

- 数量语义是「币数量」，**不做 `ctVal/ctMult` 合约面值换算**；名义价值 = 开仓价 × 数量。
- 计划风险 = `|开仓价 - 止损价| × 数量`；R = `|止盈-开仓| / |开仓-止损|`。
- 止损止盈校验：LONG `SL < entry < TP`；SHORT `SL > entry > TP`。
- 本地订单与未来实盘持仓必须分开展示，禁止相加。

## 7. 冻结区（不得修改）

以下文件的计算结果构成历史预测与绩效基线，任何新功能只能调用，不能改分支、权重或输出语义：

- `backend/app/model/market_score.py`（五维评分）
- `backend/app/services/signal_engine.py`（信号生成）
- `backend/app/services/indicator_service.py`（指标）
- `backend/app/services/direction_tracker.py`（方向抖动控制）
- `backend/app/services/future_validator.py`（回验状态机；除非另立项目扩展 horizon）

**自检方式：**

```powershell
git diff --stat -- backend/app/model/market_score.py backend/app/services/signal_engine.py backend/app/services/indicator_service.py backend/app/services/direction_tracker.py backend/app/services/future_validator.py
```

输出必须为空。

**旁路原则**：新指标写入独立字段/独立表（如 `prediction_context`、`order_flow_snapshots`），不得回灌 `score/direction/risk`，不得改变 `predictions` 的数量与节流规则。

## 8. 工程约束

| 约束 | 具体要求 |
|---|---|
| 版本单一真源 | 只改根目录 `VERSION`；后端由 `core/config.py` 读取为 `APP_VERSION`；禁止在代码里硬编码版本 |
| 打包约定 | `backend/OKEworkplace.spec`；新增第三方依赖或动态导入需补 `hiddenimports`；打包产物只带 `.env.example` |
| 禁止假数据 | 不允许用随机数、占位行情或 mock 数据冒充真实数据；数据未就绪返回 `available=false/pending=true` + `reason` |
| 证书与代理 | `oke_client.py` 显式使用 `certifi`，避免系统 `CURL_CA_BUNDLE/REQUESTS_CA_BUNDLE` 污染；代理顺序为环境变量 → Windows 注册表 → `.env` → 直连；线程内复用 Session |
| SQLite 兼容 | `signals.db` 与 `user_trades.db` 均启用 WAL + `busy_timeout`；迁移只用 `CREATE TABLE IF NOT EXISTS` 与 `ALTER TABLE ADD COLUMN`，不得要求用户删库 |
| 时间与价格 | 时间统一 ISO 8601 UTC（`+00:00`）；预测相关价格统一 `candle_close` |
| 接口便宜 | 新增 GET 只读服务层缓存；外部取数只发生在调度任务；GET 不得触发 OKX 请求 |
| 降级可读 | 数据未就绪返回 200 + 明确状态，不抛 5xx |
| 前端刷新 | `main.js` 1 秒行情/订单、2 秒分析、10 秒 MTF/订单流；新接口必须扛得住这个频率 |
| 本地安全 | Host/Origin 白名单；桌面模式写操作需 `x-oke-token`；CORS 仅本机 |
| 配置 | `.env` 开发放 `backend/.env`，打包版优先 exe 同级；真实 `.env` 不入库、不出包 |
| 提交 | 不在并行封包/改造期间提交或覆盖他人改动；不 `git add -A` 盲提交 |

**关键环境变量**（详见 `backend/.env.example` 与 `core/config.py`）：

`OKE_BASE_URL`、`OKE_API_KEY`、`OKE_SECRET_KEY`、`HTTP_PROXY/HTTPS_PROXY`、`POLL_INTERVAL_SECONDS`、`OKE_PREDICTION_MIN_INTERVAL_MINUTES`、`OKE_VERIFY_*`、`OKE_MTF_*`、`OKE_ORDERFLOW_*`、`OKE_SIGNAL_RETENTION_DAYS`、`OKE_BACKUP_*`、`OKE_ENABLE_SHUTDOWN`、`OKE_LOCAL_TOKEN`。

> 注意：当前 Key 仅用于公共行情，`oke_client.py` 未做私有签名；也没有 `OKE_API_PASSPHRASE`。实盘接入时必须新增，不要复用现有公共客户端。

## 9. 当前未做的事（不要假设已存在）

1. **没有任何私有账户能力**：无余额、无真实持仓、无保证金率、无成交记录、无下单/撤单。
2. **本地订单不是交易所订单**：`orders` 表是手工记账，不与 OKX 同步。
3. **订单流是 REST 采样**：存在漏单，`gap_suspected` 会为 true；`session_cvd` 进程重启归零；旧 `signal["cvd"]` 是快照求和，未按 tradeId 去重，新模块未覆盖它。
4. **多周期的 OI/资金费率是币种级共用值**（`shared_inputs=true`），不是逐周期数据。
5. **`capital_behavior` 保持 `unavailable`**，第 5 步已定稿不恢复。
6. **绩效页尚未展示上下文分桶**：后端 `/api/v3/performance/context-summary` 已就绪，前端 `PerformanceCard.js` 属另一会话成果，接入前需协调。
7. **无 WebSocket**：行情与订单流均为 REST 轮询。
8. **无期货合约面值换算**：数量语义固定为币数量。
9. **自动化测试很少**：只有 `backend/tests/test_smoke.py` 一个冒烟脚本，覆盖有限；主要验证以接口实测和浏览器手工回归为主。
10. **单进程单机**：无多实例、无任务队列、无对外鉴权体系（仅本地 token）。

## 10. 给 GPT 的工作规则

### 10.1 提方案时必须遵守

1. 先读本文件与第 5/6 步文档，**不要臆造已有接口或字段**；不确定就标注「需确认」。
2. 新功能默认**旁路**：新表、新字段、新接口，不改冻结区，不回灌评分。
3. 所有数据库变更必须**增量兼容**（`IF NOT EXISTS` / `ADD COLUMN`）。
4. 所有对外接口要说明：方法、路径、请求体、响应体、降级行为、是否触发外部请求。
5. 所有涉及资金的方案必须包含：权限最小化、人工确认点、上限、熔断、杀开关、审计。
6. 禁止用 mock/随机数据作为方案的一部分；可以给示例响应，但要标明是示例。
7. 涉及实盘/自动交易时，先给风险与回测门槛，再谈功能。
